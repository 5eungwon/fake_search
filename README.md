# 집온 — 원거리 주택 외부 점검 PMF 랜딩페이지

기존 FitView 페이지를 집온으로 교체했습니다. Next.js 16 / React 19 기반이며, 신청 모달과 저장 API, 보호된 실험 요약·CSV 내보내기를 포함합니다.

## 실행

```sh
npm install
cp .env.example .env.local
npm run dev
```

http://localhost:3000 에서 확인합니다. 개발에서는 신청과 이벤트가 `.data/experiment.json`에 저장됩니다. 실제 연락처는 Git에 포함되지 않습니다.

## Upstash 연결

`.env.local` 파일에 Upstash Console의 해당 Redis DB에 표시된 `UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN`을 입력합니다. 토큰은 쓰기 권한이 있는 REST 토큰이어야 합니다. 이 파일은 Git에서 제외됩니다.

```sh
npm run check:redis
```

이 명령은 고유한 테스트 키에 쓰기·읽기·삭제를 수행하고, URL이나 토큰을 출력하지 않습니다. 성공 후 개발 서버를 재시작하세요. 배포 시에는 동일한 값을 호스팅 서버의 환경변수에도 등록해야 합니다.

## 실제 모집 전 설정

- `UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN`: Upstash Redis의 REST 연결 정보. 프로덕션에서 신청과 이벤트를 영구 저장하는 데 필요합니다. 레코드 TTL은 90일입니다.
- `PMF_ADMIN_TOKEN`: 임의의 긴 비밀 값. 운영자 통계와 신청 CSV를 보호합니다. 브라우저 코드에 노출하지 마세요.
- 위 저장소가 연결되지 않은 프로덕션에서는 API가 503을 반환하며 접수 완료로 표시하지 않습니다.
- 단일 프로세스 서버에 영구 볼륨이 있을 때만 `PMF_DATA_DIR`로 파일 저장을 명시할 수 있습니다. 서버리스 / 여러 인스턴스에는 Redis를 사용하세요. 파일 저장은 요청 시 90일 지난 레코드를 정리하므로, 실제 운영에는 Redis TTL을 권장합니다.
- 개인정보 수집 안내의 운영 주체와 실제 문의 창구를 운영팀 정보로 확정한 뒤 공개하세요. 현재는 시범 운영 연락에 회신해 철회를 요청하도록 안내합니다.
- 주택의 정확한 주소·부재 일정·열쇠 정보는 수집하지 않습니다.

기존 Next.js 호스팅(Vercel 등)에 배포 가능한 소스입니다. 이번 작업에서는 공개 배포나 결제 연동을 하지 않았습니다.

## 페이지와 신청 흐름

문제 제시 → 샘플 리포트 → 방문 절차·제외 범위 → 월 9,900원 유료 이용 예약 → 2단계 폼 → 사전 신청 완료 시 자동 쿠폰 발급.

- 가칭 브랜드: 집온. 실제 점검 후기나 고객 수, 검증되지 않은 수치는 넣지 않았습니다.
- 월 1회 9,900원은 가격 가설입니다. 최종 조건 확인 전에는 결제하거나 방문을 확정하지 않습니다.
- 신청 1단계: 소유/관리 여부, 주택 유형, 시·군, 마지막 방문, 최근 방문 목적, 현재 확인 방법.
- 신청 2단계: 희망 주기, 가격 수용/망설임 이유, 연락처, 필수 개인정보 동의와 별도 선택 인터뷰 동의. 유료 이용을 선택하면 월 9,900원 이용 의향 확인이 추가로 필수입니다. 부정적 반응은 `이용 의견 남기기`로 저장하며 유료 예약이나 쿠폰 발급에 포함하지 않습니다.
- 요금과 혜택 설정은 `lib/offer.ts`에서 관리합니다. 제시한 요금·버전을 서버에서 기록하므로 기존 15,000원 신청과 새 9,900원 예약을 CSV에서 구분할 수 있습니다.
- 유료 이용 의향을 확인한 사전 신청이 완료되면 쿠폰이 자동 발급되며 실제 서버에 고유 코드가 저장됩니다. 쿠폰 발급에만 실패하면 신청을 보존하고 완료 화면에 발급 재시도 버튼을 표시합니다. 기본 혜택은 첫 결제 1,000원 할인(기본 요금 기준 첫 결제 8,900원, 이후 월 9,900원)입니다. 예약 접수일부터 90일, 첫 결제 1회, 다른 할인 중복 불가, 점검 가능 지역에 한해 사용합니다. 예약에 포함된 연락처 외에 추가 정보를 수집하지 않습니다.
- 쿠폰 코드와 유효기간은 완료 화면과 운영자 CSV에 표시됩니다. 같은 예약에서 반복 발급을 요청해도 동일 코드를 반환합니다. 결제 연동은 아직 없으므로 실제 결제 때 운영팀이 코드와 사용 이력을 확인하고 할인을 적용해야 합니다.
- 샘플 리포트는 `특이사항 없음`, `이상 발견`, `확인 불가`를 탭으로 확인할 수 있습니다. 샘플 이미지와 관찰 결과는 실제 점검 증거가 아닙니다.
- 접수 API는 필수값, 선택지, 연락처와 동의를 서버에서 검사합니다. 동일 신청을 다시 전송해도 중복 저장하지 않습니다.

## 실험 지표

`POST /api/track`: `landing_view`, `apply_click`, `report_view`, `form_start`, `form_step_complete`를 기록합니다. 신청 완료 수는 실제 저장된 신청 레코드에서 계산합니다.

유입 URL 예시:

```text
/?utm_source=naver_cafe&utm_campaign=pilot_01&utm_content=distance
/?utm_source=naver_cafe&utm_campaign=pilot_01&utm_content=favor
```

`utm_content`는 모집글 메시지를 구분하는 값입니다. 페이지 문구 자체를 바꾸는 A/B 기능은 아닙니다. 같은 대상·비슷한 노출 조건에서 비교하세요.

`GET /api/experiment`에 `Authorization: Bearer <PMF_ADMIN_TOKEN>` 헤더를 보내면 이벤트 횟수, 저장된 신청 수, 유입 경로별 신청·실제 관리 주택 보유 여부·유료 이용 의향·요금 확인을 마친 유료 예약(`paidReservations`)·실제 쿠폰 발급(`couponsIssued`)을 확인합니다. `?format=csv`로 신청 레코드를 내려받을 수 있습니다. 인증 없는 요청은 401을 반환합니다. 통계 응답에 연락처나 쿠폰 코드를 포함하지 않으며 CSV에만 포함합니다. CSV에는 `offeredPrice`, `offerVersion`, `priceConfirmed`, `couponCode`, `couponDiscount`, `couponIssuedAt`, `couponExpiresAt`도 포함합니다.

이벤트는 **발생 횟수**이며 고유 방문자/고유 신청자 전환율이 아닙니다. 새로고침이나 반복 클릭도 집계됩니다. 같은 접수 ID의 재시도는 한 건으로 저장하지만, 새 접수 ID로 다시 신청한 동일 연락처는 별도 레코드이므로 모집 분석 시 확인하세요. 유료 예약과 쿠폰 발급을 별도로 집계합니다. 둘 다 실제 결제는 아니므로, 이후 쿠폰 적용 첫 결제와 할인 없는 재결제를 별도로 기록해야 합니다. 랜딩페이지에서 확인할 수 있는 것은 참여 의향과 가격 반응이며, PMF나 실제 구매의 증거는 아닙니다.

## 다음 검증

1. 2주 동안 실제 관리 중인 주택의 소유자·관리자 5명 이상 모집을 초기 실험 목표로 둡니다. PMF 통과 기준이 아닙니다.
2. 최근 방문 목적이 `집의 외부 상태 확인`인 신청자를 우선 인터뷰하고, 외부 리포트가 어떤 방문을 대신하는지 확인합니다.
3. 한 지역에서 범위를 합의하고 실제 결제 → 점검 완료를 기록합니다. 랜딩페이지 신청 수와 분리합니다.
4. 점검 전 방문 계획과 결과 이후의 실제 방문 여부를 기록하고, 다음 점검 **재결제**를 확인합니다.
5. 지역 주민의 이동·작업 시간, 보수 만족과 플랫폼 검수·응대 비용도 함께 기록합니다.
